# Simulation/resampling design memo (v3.1 refocus)

RoBMA-PSMA rigor-estimand workflow for systematic evidential auditing.

This memo is the design document. It stays conceptual and ADEMP-shaped. The README owns the live run commands and file paths (default `B`, the canonical Phase A-D sequence, file provenance, etc.); this memo describes what the layer is and why, not how to run it. The nutrition corpus is the worked empirical example; the simulation itself is a general methods exercise for the audit workflow.

### Registry / data-mart handoff

The evaluated audit workflow is not complete at the sidecar stage. Fitted outcomes are first reduced to v4 sidecars, then rebuilt into the canonical outcome registry by the main pipeline's `build_estimand_tables()`. Synthetic resampling and composition operate on that registry rather than directly on sidecars, so the registry rebuild is a formal handoff in the method pipeline, not a convenience step. The per-cell `n_fit` reported by 55's sidecar diagnostics and the per-cell `n_pool` consumed by 65's synthetic resampling are two different quantities at two different layers: when they disagree, the registry is stale and the evaluated workflow has not been refreshed end-to-end.

### Monte Carlo repetitions

`B` and `n_reps` are independent design quantities and must not be conflated:

- **`B`** is the resampling / sampling replicate count. It controls the Monte-Carlo precision of the resampling summary. The operating tiers are `B = 500` (development / visual tuning; default), `B = 5000` (high-precision internal checking), and `B = 15000` (final / publication when feasible). Increasing `B` shrinks the width of the Monte-Carlo confidence on the resampling summary; it does **not** smooth away empirical finite-support roughness driven by the fitted library.
- **`n_reps`** is the per-target-cell depth of the fitted synthetic library generated by `sim_generate_library()`. Current primary depth is `n_reps = 150` per cell. `n_reps = 500` per cell is available as an optional finite-library sensitivity if `cell_diagnostics_rigor.csv` reports borderline `n_fit` per cell relative to the cells the analysis leans on; it is not an automatic upgrade.

`B` governs Monte-Carlo precision; `n_reps` governs finite-library precision. The README owns the run commands and the tier table; this memo describes the conceptual distinction only.

## 1. Design stance

The simulation/resampling layer answers three primary questions:

| Question | Plain-language target | Current layer | Manuscript role |
|---|---|---|---|
| **Q1. Known-cell behavior** | How does the audit workflow behave under constructed effect x heterogeneity x bias-burden regimes? | full36 synthetic library + cell diagnostics | main methods-simulation evidence |
| **Q2. Empirical resampling stability** | If we resample the observed empirical nutrition corpus, how stable are the rigor summaries? | empirical Track A resampling | empirical robustness/stability evidence |
| **Q3. Empirical-weighted synthetic sampling** | Given cell-mixture distributions derived from empirical strata, how do synthetic samples with those distributions behave? | empirical-weighted synthetic sampling + agreement | bridge between the methods library and the empirical worked example |

Everything else is diagnostic. In particular, fitted-cell transition maps, target provenance, observed-cell recovery, and synthetic pool support are useful for debugging the Q3 sampling machinery, but they are not primary research questions.

The design should not be described as a nutrition calibration study. It is a methods simulation for a reusable evidential-audit workflow, with nutrition used as the first empirical application.

## 2. Terminology guardrail: `k_studies` vs `n_outcomes`

The current workflow needs a strict naming distinction:

| Name | Meaning | Where it appears |
|---|---|---|
| `k_studies` or `k` | number of studies inside one meta-analytic outcome dataset | synthetic DGM, study-geometry checks, generated dataset metadata |
| `n_outcomes` | number of outcome-level meta-analyses summarized inside a stratum/corpus draw | empirical resampling, empirical-weighted synthetic sampling, cell-size curves |

The 5-30 range that matters for stratum stability is usually **`n_outcomes`**, not `k_studies`. The existing DGM already draws `k_studies` from the shared marginal study-count sampler. The analytical focus is the behavior of stratum-level summaries when `n_outcomes` is small to moderate, especially 5-30; this is now covered by the Q1 width / viability family built from `synthetic_cell_size_curve_summary.csv`.

If the scientific question is literally about the number of studies within each individual meta-analysis, then the clean design is a fixed-`k_studies` DGM ladder that generates and refits new datasets. That is a heavier future extension. The current design uses the fitted full36 library to ask how summaries behave as `n_outcomes` grows.

## 3. ADEMP specification

### 3.1 Aims

The focused ADEMP aims are:

1. **Known-cell operating behavior.** Estimate the selected-rigor profile returned by the workflow under each 36-cell DGM cell and show how the stratum-level summary varies as `n_outcomes` grows in the empirically relevant 5-30 range. Q1 also evaluates the core audit components needed to interpret selected rigor in each cell — bias evidence and absolute attenuation / effect recovery — as a paired diagnostic, not a loose appendix.
2. **Empirical resampling stability.** Estimate uncertainty/stability in observed empirical stratum and corpus rigor summaries under outcome-level and source-cluster resampling.
3. **Empirical-weighted synthetic sampling.** Use empirical stratum cell-mixture weights to sample fitted synthetic rows and ask whether those empirical-weighted synthetic profiles reproduce the empirical rigor profiles. (Q3 is not a new DGM; it is empirical-weighted sampling from the fitted synthetic library.)

Secondary aims:

- Check raw input-geometry parity between empirical and synthetic datasets.
- Audit synthetic pool support and fitted transition/provenance structure.
- Preserve enough diagnostics to explain failures rather than hiding them.

### 3.2 Data-generating and resampling mechanisms

**Q1 uses synthetic DGM cells.** Each generated dataset belongs to one target cell:

```text
effect_slug x heterogeneity_slug x bias_slug
4 x 3 x 3 = 36 cells
```

The cell anchors are:

| Axis | Levels | DGM anchor |
|---|---|---|
| effect | `null`, `small`, `moderate`, `large` | `mu_true = 0.00, 0.10, 0.25, 0.50` |
| heterogeneity | `lowhet`, `midhet`, `highhet` | `tau_true = 0.05, 0.15, 0.40` |
| bias burden | `clean`, `modbias`, `highbias` | threshold-selection weights plus `smallstudy_alpha = 0.00, 0.25, 0.50` |

**Q2 uses empirical resampling.** The data-generating mechanism is unknown; we study the empirical sampling distribution by resampling observed registry rows. The two primary modes are:

- `outcome`: resample outcome rows with replacement within each empirical stratum.
- `source_cluster`: resample `source_article` clusters with replacement within each empirical stratum.

**Q3 uses empirical fitted-cell-weighted synthetic sampling.** Two distinct cell concepts share one 36-cell vocabulary; conflating them is the central interpretive risk:

- **Synthetic target cell (DGM cell).** Known by construction from `effect_slug x heterogeneity_slug x bias_slug`. Defined by 10/20/40; not by 65.
- **Empirical fitted-cell assignment (fitted profile cell).** A deterministic projection of an empirical outcome onto the same 36-cell vocabulary using its fitted audit outputs (`|mu_BC|`, `tau_BC`, `log10BF_bias`) and the band thresholds documented in `sim_assign_observed_cell()`. Not a true generative label and not evidence the empirical outcome came from a synthetic regime.

Q3 builds per-stratum fitted-cell mixture weights, then samples fitted synthetic outcomes from the synthetic library under those weights. The internal column `observed_cell_slug` is a technical handle for the fitted-cell assignment; public language (reports, figure captions, manuscript prose) says "fitted-cell assignment" or "fitted profile cell" instead.

**Primary Q3 weighting (recommended): empirical-Bayes support-masked (`smoothing = "eb_corpus"`, `kappa = 4`, `support = "occupied"`).** For each stratum `s` and fitted profile cell `c`:

```text
w_sc = (n_sc + kappa * p0_{c|s}) / (n_s + kappa)
```

where `n_sc` is the stratum's count on cell `c`, `n_s` is its assigned-outcome count, `kappa` is the prior pseudo-count, and `p0_{c|s}` is the corpus fitted-cell distribution restricted and renormalized over the cells the stratum occupies (`support = "occupied"`). The effective stratum-vs-corpus mixing weight is `lambda_eff = n_s / (n_s + kappa)`; small strata shrink more aggressively toward the restricted corpus prior. By construction the weights sum to 1 over a stratum's occupied cells. The legacy `corpus_blend`, `additive`, and `none` options remain available for sensitivity but are not the default.

Pool basis: the primary `pool_key = "target"` indexes the synthetic library by its DGM target cell. `pool_key = "observed"` (the same library indexed by its own fitted-cell assignment) is a sensitivity analysis only.

Q3 is not a new DGM, not a calibration mechanism for the empirical corpus, and not evidence the empirical outcomes came from the synthetic regimes. It is a bridge: under empirically derived fitted-cell mixtures, how do summaries from a synthetic library with known DGM truth behave, and how do those bands compare to empirical resampling bands at matched sample sizes?

### 3.4 Methods

The evaluated method is the full audit workflow:

```text
audit-ready dataset
-> v4 loader
-> matched NoBMA/random-effects baseline
-> RoBMA-PSMA fit
-> v4 sidecar
-> outcome registry
-> rigor summaries
-> resampling/composition summaries
```

No downstream layer should reimplement the selected-rigor definitions. Empirical and synthetic summaries must use the same reducers.

### 3.5 Performance measures

For Q1, report by cell and by cell-size curve:

```text
n_generated, n_fit, n_pool
median/q05/q95 log10BF_rigor
median/q05/q95 rigor_margin
P(rigor_direction = effect)
P(rigor_direction = no_effect)
P(clean effect support)
P(clean no-effect support)
P(clean evidence disfavored)
MCSE for binary rates
```

For Q2, report:

```text
observed empirical estimate (for core audit metrics)
bootstrap mean/sd
q05/q95 and q025/q975 by mode
width90 = q95 - q05 (primary stability scale)
observed stratum size and source-cluster count
sample-size curve over n_sampled where implemented
non-finite width / endpoint flags (preserved, not dropped)
```

For Q3, report:

```text
empirical estimate
synthetic median
synthetic q05/q95 and q025/q975
absolute and standardized difference
empirical percentile under synthetic composition
interval-overlap flag
empirical-bootstrap interval alongside synthetic-composition interval when available
```

Monte Carlo uncertainty is required for operating-characteristic claims. For a binary rate, use:

```text
MCSE = sqrt(p * (1 - p) / n)
```

Worst-case MCSE occurs when `p = 0.5`:

| Repetitions | Worst-case MCSE |
|---:|---:|
| 25 | 0.100 |
| 100 | 0.050 |
| 150 | 0.041 |
| 250 | 0.032 |
| 500 | 0.022 |
| 5000 | 0.007 |
| 15000 | 0.004 |

### 3.6 Morris / ADEMP framing

Q1, Q2, and Q3 evaluate the same audit method (RoBMA-PSMA -> v4 sidecar -> registry -> rigor summaries) under three different mechanisms; the method/estimands are fixed across mechanisms:

| Question | Mechanism | What changes between draws |
|---|---|---|
| Q1 | known synthetic DGM (full36 library) | the underlying target cell is fixed and known; draws differ only in finite-sample variability of the fitted summary at a given `n_outcomes` |
| Q2 | empirical resampling | the empirical registry is fixed; outcome rows / `source_article` clusters are resampled with replacement |
| Q3 | empirical-fitted-profile-weighted sampling from the fitted synthetic library | the empirical fitted-cell mixture is fixed per stratum; synthetic rows are sampled under that mixture |

The estimand list does not change across Q1/Q2/Q3. Performance summaries are the same selected-rigor + core audit metrics in all three layers, which is why the bridge comparisons in 70 can speak to method behavior rather than to which mechanism produced which row.

### 3.7 Overclaim guardrails

Q3 is a bridge. The interpretive risk is treating an empirical fitted-cell assignment as a generative label. The following claims are explicitly out of scope; do not use them in the manuscript or in figure captions:

- "Empirical outcomes are assigned to DGM cells." (They are deterministically **projected** into fitted profile cells, not assigned to DGM cells.)
- "Q3 is a calibration DGM" / "Q3 is an empirical DGM". (Q3 is not a DGM at all; it is empirical-fitted-profile-weighted sampling from a fixed fitted synthetic library.)
- "The empirical outcomes came from the synthetic regimes." (Their fitted-cell assignment is a deterministic projection; nothing in 65 or 70 establishes a generative claim.)
- "True cell assignment" / "ground-truth fitted cell". (The fitted-cell assignment is a posterior-style projection, not a ground-truth label. The boundary-near diagnostic at `detail/empirical_fitted_cell_boundary_diagnostics.csv` exposes the sensitivity that wording would hide.)

Acceptable framings:

- "Empirical fitted-cell-weighted synthetic sampling."
- "Q3 is a bridge between empirical corpus structure and known-cell synthetic behavior."
- "Under each stratum's empirical fitted-cell mixture, how do summaries from a synthetic library with known DGM truth behave, and how do those bands compare to empirical resampling bands at matched sample sizes?"

These guardrails are a writing contract, not a code contract; the underlying code remains identical.

### Q1. Known-cell behavior

This is the main methods-simulation evidence.

#### Q1a. Outcome-level cell diagnostics

Existing cell diagnostics answer:

> Across fitted synthetic datasets generated under a known target cell, what selected-rigor profile does the workflow return?

These outputs should remain:

```text
simulation/results/cell_diagnostics_rigor.csv
simulation/results/cell_diagnostics_component.csv
```

The plots should show the 36 target cells directly, not through empirical strata. Recommended figures:

1. **Full36 selected-rigor heatmap.** Rows = effect x heterogeneity, columns/facets = bias burden, fill = selected metric.
2. **Full36 cell lollipop/small multiples.** One row per target cell, primary rigor rates with MCSE intervals.
3. **Cell behavior by `k_studies` bucket.** Diagnostic only; useful for showing whether study count inside a meta-analysis is driving anomalies.

#### Q1b. Synthetic known-cell `n_outcomes` curve

Question:

> If a stratum consisted of `n_outcomes` fitted outcomes drawn from the same known synthetic target cell, how stable and interpretable would the selected-rigor summaries be as `n_outcomes` grows from 5 to 30?

Procedure:

```text
For each target cell t:
  define pool = fitted synthetic rows with target_cell_slug == t
  for n_outcomes in c(5:30, 35, 40, 50):
    for b = 1..B:
      sample n_outcomes rows from pool with replacement
      summarize using emp_stratum_summary()
      record cell, n_outcomes, b, metric values
```

This does **not** refit RoBMA. It resamples already fitted synthetic outcomes and summarizes them as hypothetical strata. That makes it cheap, directly tied to the current full36 library, and aligned with the empirical stratum-size problem.

Outputs (size-curve summary + draws, written by 65):

```text
simulation/results/cell_behavior/synthetic_cell_size_curve_summary.csv
```

### Q2. Empirical resampling stability

Current Track A already asks the right question, but the figures need to show the resampling process explicitly.

Question:

> If the empirical nutrition outcome database is resampled, how stable are the observed stratum and corpus rigor profiles?

Single public workflow (`B` tiers: 500 dev / 5000 internal high-precision / 15000 final; see README for live commands and tier table):

```r
emp_run_resampling(B = 500,
                   n_grid = c(5:30, 35, 40, 50, 75, 100))
```

Current outputs (five stable files):

```text
simulation/results/empirical_resampling/empirical_resampling_observed.csv
simulation/results/empirical_resampling/empirical_resampling_size_curve.csv
simulation/results/empirical_resampling/empirical_resampling_size_curve_summary.csv
simulation/results/empirical_resampling/empirical_resampling_observed_size_intervals.csv
simulation/results/empirical_resampling/empirical_resampling_report.md
```

The scaling curve covers both `level == "stratum"` and `level == "corpus"`. Each group's observed `n_outcomes` (in `outcome` mode) and `n_source_articles` (in `source_cluster` mode) is auto-inserted into the grid so `empirical_resampling_observed_size_intervals.csv` is always populated for every (group, mode) cell.

Empirical resampling evaluates **stability** of the observed stratum/corpus summaries under outcome-row and source-article-cluster resampling, not a new synthetic data-generating mechanism. The primary stability measure is `width90 = q95 - q05` (lower = more stable). Default Q2 visuals focus on the **core audit metric set**:

- `median_log10BF_rigor` (selected rigor)
- `median_rigor_margin` (rigor margin)
- `median_log10BF_bias` (bias evidence)
- `median_attenuation_abs` (absolute attenuation)

Directional / thresholded `p_*` rate metrics (`p_rigor_direction_effect`, `p_rigor_direction_no_effect`, `p_clean_effect_supported`, `p_clean_no_effect_supported`, `p_clean_evidence_disfavored`, `p_inconclusive_clean_evidence`) remain in `empirical_resampling_size_curve_summary.csv` as descriptive outputs for ad-hoc inspection but are **not default Q2 visual targets** — the selected-rigor estimand is designed to abstract away from per-cell directional bookkeeping.

Default visuals (built by `sim_run_empirical_resampling_visuals()`, exactly three PDFs):

1. **Rigor variability by stratum** — `width90` of selected rigor over `n_sampled`, one line per empirical stratum, faceted by bootstrap mode (`outcome` and `source_cluster`). Reads `empirical_resampling_size_curve_summary.csv`.
2. **Core uncertainty heatmap** — observed-size `width90` across the four core audit metrics, faceted by bootstrap mode. Reads `empirical_resampling_observed_size_intervals.csv`. Non-finite widths are preserved (labelled `Inf`, fill clamped to the terminal color).
3. **Core observed-size intervals** — forest/range profiles per (stratum, core metric, bootstrap mode); filled point = observed empirical estimate, thick bar = q05-q95, thin bar = q025-q975. Non-finite endpoints are clamped to a per-facet terminal axis boundary so rows stay visible.

Corpus-level Q2 information is retained as a markdown core-metric summary table inside `empirical_resampling_visuals_report.md` rather than as separate default PDFs.

The stratum-agreement figure should not be the first place a reader sees empirical resampling. Empirical resampling needs its own visual family.

### Q3. Empirical-weighted synthetic sampling

Question:

> Given distributions of cells derived from empirical strata, how do synthetic samples with those distributions behave?

Q3 evaluates four things, in this order:

1. **Empirical fitted-cell mixtures.** For each empirical stratum, the observed/fitted cells implied by `abs(mu_BC)`, `tau_BC`, and `log10BF_bias`. Those fitted-cell profiles define corpus-blended empirical-weighted sampling weights (default `lambda * stratum_p + (1 - lambda) * corpus_p`, blended only over the cells the stratum actually populates and then renormalized — not spatial smoothing over the 36-cell grid).
2. **Stability of empirical-weighted synthetic sampling summaries** as `n_outcomes` grows, framed as sampling variability (`width90 = q95 - q05`) of the stratum-level summary across B empirical-weighted synthetic draws rather than as the mean/median level.
3. **Agreement / contrast between empirical bootstrap and empirical-weighted synthetic sampling** for the core audit metrics (`median_log10BF_rigor`, `median_rigor_margin`, `median_log10BF_bias`, `median_attenuation_abs`). Directional/thresholded `p_*` rate metrics are deliberately excluded from this comparison — the selected-rigor estimand is designed to abstract away from per-cell directional bookkeeping.
4. **Profile-definition diagnostics** via per-axis recovery (effect, heterogeneity, bias) to confirm whether the fitted cell-assignment basis recovers the intended design axes. These maps justify / interrogate the fitted-cell basis used for Q3 empirical-weighted sampling.

Q1 known-cell behavior is **not** being merged with Q3: Q1 is known-cell / target-cell behavior of the synthetic library on its own design regime, while Q3 is empirical-profile-weighted mixture / sampling behavior of that same library.

## 6. Implementation implications for scripts 60-75

### 60_empirical_resampling.R

One public workflow function — the scaling curve is now the primary object, and observed-size intervals are derived from it. Visual-ready fields are exposed on every output row:

```text
level, stratum, bootstrap_mode, n_sampled, n_pool,
n_outcomes_observed, n_sources_observed, metric,
observed_value, bootstrap_mean, bootstrap_sd,
q025, q05, q050, q95, q975,
interval_width_90, interval_width_95, bias_vs_observed,
n_bootstrap, B
```

Single call (default `B = 500`):

```r
emp_run_resampling(B = 500,
                   n_grid = c(5:30, 35, 40, 50, 75, 100),
                   modes  = c("outcome", "source_cluster"))
```

`n_grid` covers both stratum-level and corpus-level curves; each (group, mode)'s observed `n_outcomes` / `n_source_articles` is auto-inserted so `empirical_resampling_observed_size_intervals.csv` is always non-empty.

Use `n_outcomes`, not `k`, in all output columns and plot labels — `n_sampled` counts outcome-level meta-analyses or source clusters, not primary studies inside a meta-analysis.

### 65_synthetic_resampling.R

Keep empirical-weighted synthetic sampling. Both sweep products are part of the script, normally invoked via the operator-facing `sim_run_synthetic_resampling()`. Lower-level signatures (default `B = 500`; pass larger explicitly for final runs):

```r
sim_run_cell_size_curve(B = 500,
                        n_grid = c(5:30, 35, 40, 50),
                        pool_key = "target")

sim_run_empirical_weighted_size_curve(B = 500,
                                      n_grid = c(5:30, 35, 40, 50),
                                      pool_key = "target",
                                      smoothing = "eb_corpus",
                                      kappa     = 4,
                                      support   = "occupied")
```

Both reuse `emp_stratum_summary()` / `emp_corpus_summary()` and write stable filenames with `B` and `n_outcomes` in row columns, not filenames. Transition/provenance/support outputs remain available under diagnostic/provenance language, not as primary Q3 evidence. The lower-level Q3 runners were renamed in the 2026-05 terminology pass (`sim_run_synthetic_composition` → `sim_run_empirical_weighted_synthetic`; `sim_run_composition_size_curve` → `sim_run_empirical_weighted_size_curve`); deprecation aliases under the old names are kept for one release cycle.

## 7. Acceptance criteria for the refocus

The refocused analysis is ready when:

1. The memo and README describe exactly three primary questions.
2. Figure titles reveal whether a plot is cell behavior, empirical resampling, or empirical-weighted synthetic sampling.
3. The observed-cell / target-cell transition machinery is diagnostic, not the center of the story.
4. Q1 includes a known-cell `n_outcomes` curve over 5-30.
5. Q2 includes empirical resampling interval plots where the bootstrap mode is visible.
6. Q3 includes empirical-weighted synthetic sampling figures where the draw mechanism is visible.
7. Q3 includes empirical-bootstrap vs empirical-weighted-synthetic interval overlays.
8. All outputs use `n_outcomes` for stratum sample size and reserve `k` for studies inside a meta-analysis.
9. All binary-rate claims report or imply Monte Carlo uncertainty.
10. No figure filename encodes B, replicate tier, or pilot/dev status.

## 8. Reference positioning

Morris, White, and Crowther's ADEMP framing remains the design model: aims, data-generating/resampling mechanisms, estimands, methods, and performance measures. Their core reporting lesson applies directly here: simulation studies are finite Monte Carlo experiments, so the design and Monte Carlo uncertainty must be visible rather than implied.
